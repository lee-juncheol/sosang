# 사진 보내기 (데스크톱 앱)

PhotoCourier(Swift, macOS 전용)의 선별·전송 기능을 sosang 앱으로 옮긴 화면입니다. 앱 상단 메뉴 **사진 보내기**(`#send`)에 있고 웹사이트에는 나타나지 않습니다.

## 범위

- JPG / JPEG만 다룹니다. HIF·HEIC는 아직 다루지 않습니다(HEVC 디코더를 Mac·Windows 양쪽에 넣는 문제, 사용성을 보고 결정).
- 보정은 **수평 회전(±15°, 0.1° 단위)**만 있습니다. 빛·색 보정, 수직 원근, 자동 맞춤, 히스토그램은 옮기지 않았습니다.
- 사진 처리는 모두 Rust(`crates/photo-courier`)에서 합니다. 화면(WebView)은 Rust가 만든 축소 미리보기를 CSS `rotate(-θ) scale(zoom)`로 돌려 보여 주고, 저장은 같은 각도·확대 값으로 원본 해상도에서 다시 계산합니다.

## 동작

- 원본 폴더(하위 폴더 포함 선택), 날짜순/이름순, 썸네일(EXIF 내장 썸네일이 사진과 비율이 같으면 사용, 아니면 1/8 디코딩).
- ↑↓ 선택, → 대기열 추가, ← 대기 취소, ⌘Enter(Windows는 Ctrl+Enter) 전송.
- 저장 형식
  - 수평 0 + WebP 끔: 원본을 바이트 그대로 복사.
  - 수평 조절: 원본 해상도 JPG(품질 96, 4:2:2). EXIF는 유지하고 방향은 1, 픽셀 크기는 새 값, 내장 썸네일 연결은 끊습니다. ICC는 그대로 넣습니다.
  - WebP 72%/100%: 손실 압축. EXIF·ICC를 WebP 확장 컨테이너에 넣습니다.
- 대상 폴더에 먼저 임시 파일(`.sosang-send-*.tmp`)로 쓰고, 빈 이름을 `create_new`로 잡은 뒤 이름을 바꿉니다. 같은 이름이 있으면 `이름_1`, `이름_2`. 실패하면 임시 파일을 지웁니다.
- 전송 중 오류가 나면 끝난 사진은 대기열에서 빠지고 남은 사진만 다시 보낼 수 있습니다.

## 검증

- `cargo test -p photo-courier`: EXIF 읽기·수정(두 바이트 순서), 방향 1–8, 수평 회전 방향·확대·빈 모서리 없음, JPG/WebP 메타데이터 왕복, 이름 충돌, 원본 그대로 복사, 폴더 탐색 제외 규칙.
- `tests/courier.test.ts`: 정렬, 표시 형식, 미리보기 확대값이 Rust 공식과 같은지.
- 2026-11-16 macOS 디버그 앱에서 확인: 14장 목록·썸네일, 미리보기, 수평 +3.6° 저장본이 미리보기와 같은 구도, 미보정 사진은 바이트 동일 복사.
- Windows에서는 아직 실행해 보지 않았습니다. `libwebp-sys`가 C 컴파일러(MSVC)로 빌드됩니다.

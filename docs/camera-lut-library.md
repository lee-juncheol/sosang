# 카메라 LUT Library 직접 등록 (USB/PTP)

LUMIX 카메라의 [LUT Library]에 SD 카드 없이 USB로 LUT를 등록하는 방법과 근거입니다. 구현은 `crates/lumix-lut`(설정 파일 해석·수정)와 `crates/lumix-ptp`(macOS 전송)에 있습니다.

**검증 범위: DC-S1M2, 펌웨어 1.5 한 대.**
- 기종 문자열이 `DC-`로 시작하고 구조 검사(항목 번호로 찾은 이름 표·LUT 레코드, 레코드 크기, 체크섬)를 통과하면 어느 LUMIX든 목록을 읽습니다.
- 쓰기는 `VERIFIED_FOR_WRITE`에 있는 기종·펌웨어만 바로 허용합니다. 그 밖의 Panasonic 기종은 사용자가 "실험적 쓰기"에 동의해야 씁니다(`Camera::allow_unverified_writes`).
- 실험적 쓰기도 같은 백업, 범위 검사, 다시 읽기 확인을 거칩니다. 다시 읽은 결과가 다르면 쓰기 전 설정을 바로 다시 쓰고, 이름 표가 쓰기 전과 같은지 확인합니다(`PtpError::RolledBack`).
- 실물로 확인한 기종·펌웨어는 `VERIFIED_FOR_WRITE`에 추가합니다.

## 출처

- LUMIX Tether 2.12 `libLmxptpif.dylib`를 정적 분석했습니다(설치본, 실행하지 않음).
  - `LmxExt_Get_SetupFilesConfigSet_Info`: 읽기 `0x9421`
  - `LmxExt_SetSetupFilesConfigSetInfo`: 쓰기 `0x9422`
  - 둘 다 파라미터 1개(`0x080000A2`)
- 앱 본체의 `setup_file_config_setting_restore_setting`은 저장해 둔 파일을 그대로 `Set_Data`로 보냅니다. 앱에는 체크섬 코드가 없습니다.
- 그 밖의 사실은 실제 카메라에서 읽고 쓴 결과와, 카메라가 SD 카드에서 직접 등록한 결과를 비교해 확인했습니다(2026-11-14).

## PTP 명령

| 명령 | 파라미터 | 데이터 | 비고 |
|---|---|---|---|
| `0x9421` | `0x080000A2` | 카메라 → PC, 설정 파일 전체 | DC-S1M2 9,197,673 바이트, 약 6초 |
| `0x9422` | `0x080000A2` | PC → 카메라, 같은 형식 | 약 11초, 응답 `0x2001` |

macOS에서는 `ptpcamerad`가 장치를 잡고 있어 libusb/WebUSB로는 열 수 없습니다(`claimInterface` 실패 확인). ImageCaptureCore의 `requestSendPTPCommand:outData:completion:`을 씁니다. 쓰기 명령의 완료 블록에는 받은 데이터 자리에 `nil`이 들어옵니다. `ICDeviceBrowser`를 멈췄다가 새로 시작하면 이미 연결된 카메라를 다시 알려 주지 않으므로, 브라우저는 프로세스가 끝날 때까지 유지하고 명령마다 세션만 열고 닫습니다.

데스크톱 앱(`src-tauri`)은 `camera_status`, `camera_list_luts`, `camera_register_lut` 명령으로 이 기능을 씁니다. 디버그 빌드에서 `SOSANG_CAMERA_SELFCHECK=1`을 주고 실행하면, 시작할 때 연결 확인과 목록 읽기를 실행하고 결과를 출력합니다(쓰기는 하지 않습니다).

## 설정 파일 구조

- 헤더: `u32 0x080000A2`, `u32 길이(전체-8)`, `u32 데이터 길이(전체-12)`, 이어서 데이터. `0x1E`에 기종 문자열 `DC-S1M2`가 있습니다.
- 마지막 1바이트는 체크섬입니다: `sum(bytes[0x0C..]) % 256 == 0`.
- 항목 형식: `[u16 항목 번호][u16 순번][u32 길이][데이터]`. 고정 오프셋 대신 아래 두 항목을 번호로 찾습니다.

### 이름 표: 항목 `0x2F4`
- 데이터: `u32 0x0A`, `u32 배열 길이(41 × 776)`, 이어서 776바이트 칸 41개.
- 칸 k: `u32 번호(=k)`, `u16 연결`, `u16 기본 스타일`, `UTF-16LE 이름(512바이트 영역)`.
  - **연결 값은 반드시 k여야 합니다.** 사용 중인 칸은 연결 = k, 빈 칸은 `0xFFFF`입니다. 다른 값을 쓰면 카메라가 엉뚱한 LUT 데이터를 적용합니다(실기 확인).
  - 기본 스타일: `0` = `#LUMIXPHOTOSTYLE STD`, `49` = 태그 없음(V-Log 기준), `37` = ARRI 709, `10` = Vlog_709.
- 칸 0은 내장 Vlog_709이며, 연결된 LUT 데이터가 없습니다.

### LUT 데이터: 항목 `0x51F`
- 데이터: `u32 0x0C`, 이어서 레코드 41개, 끝에 8바이트.
- 레코드 n(이름 표 칸 n+1과 짝): `u32 0x34A4C`, `u16 격자(33, 빈 칸은 0)`, `u16 기본 스타일(이름 표와 같은 값)`, `33³ × RGB u16 LE`(R이 가장 빨리 바뀜, `round(v × 65535)`), `u16 0`.
- 카메라가 SD 카드에서 직접 넣은 값과 이 방식으로 계산한 값은 최대 1 LSB 차이였습니다(반올림 차이).

### 삭제와 선택 상태
- 카메라가 직접 지울 때는 이름 표 칸만 바뀝니다: `연결 = 0xFFFF`, `기본 스타일 = 49`, 이름 영역 0. LUT 레코드는 그대로 남고, 칸이 비어 있는 동안에는 쓰이지 않습니다(2026-11-14 캡처 비교). `SettingsBlob::without_lut`는 이 칸을 바이트 단위로 같게 만듭니다.
- 이름 표 칸의 마지막 3바이트는 사용 여부와 관계없이 `FF FF FF`이며 건드리지 않습니다.
- 카메라 메뉴에서 고른 칸 번호 + 1은 항목 `0x52F`(순번 0, 1, 2 세 개, 데이터 28바이트)의 데이터 5번째 바이트(오프셋 4)에 같은 값으로 세 번 들어 있습니다. DC-S1M2 fw 1.5에서는 `0x8BFC84`, `0x8BFCA0`, `0x8BFCBC`입니다.
- 카메라는 선택된 LUT를 지우면 이 값을 바꾸는데, 그 규칙은 확인하지 못했습니다. 그래서 선택된 칸은 지우지 않고, 이 항목을 찾지 못한 기종에서는 지우기 자체를 막습니다(넣기는 됩니다).
- 앱은 0번(Vlog_709)과 1번(ARRI 709)은 바꾸지 않습니다.

## 등록 절차 (`lumix_ptp::register_lut`)

1. `0x9421`로 읽어서 검증합니다(헤더, 길이, 기종, 체크섬).
2. 읽은 원본을 백업 파일로 저장합니다.
3. `SettingsBlob::with_lut`로 칸 하나만 고칩니다. 바뀐 바이트가 이름 표 칸, 짝이 되는 레코드, 체크섬 밖에 있으면 실패합니다.
4. `0x9422`로 씁니다.
5. 다시 읽어서 이름과 LUT 값이 보낸 내용과 같은지 확인합니다.

## 안전 장치
- 쓰기는 카메라의 [카메라 설정 저장/복원 → 불러오기]와 같은 일로 처리되어, 카메라에 등록 안내가 뜹니다. 설정 파일 전체를 다시 쓰므로, 읽은 뒤 쓰기가 끝날 때까지(약 17초) 카메라에서 바꾼 설정은 되돌아갑니다. 앱은 그동안 "카메라를 조작하지 마세요" 화면을 띄웁니다.
- 설명서의 복사 가능 항목 표에서 빠진 항목(시계, Bluetooth, 연결 설정, Frame.io, 폴더 선택, 타임코드 값 등)은 설정 파일에 없어 바뀌지 않습니다.
- 앱은 칸마다 목록을 읽었을 때의 상태(빈 칸 또는 이름)를 함께 보냅니다. 쓰기 직전 카메라가 다르면 쓰지 않습니다(`SettingsBlob::check_expected`).
- 쓰기 전마다 설정 전체를 `{기종}-settings-{밀리초}.bin`으로 백업하고, 옆에 `.json`(기종, 펌웨어, 시리얼, 시각, 이유)을 남깁니다. 되돌리기는 시리얼·기종·펌웨어가 같은 카메라에만 하고, 다시 읽은 결과가 백업과 바이트 단위로 같아야 성공입니다.
- 2026-11-15 확인: 쓰기 다섯 번 모두 고른 칸과 체크섬 말고는 바뀐 바이트가 없었고, 쓰지 않은 동안(최대 26분, 재연결 포함) 설정 파일은 바뀌지 않았습니다. 백업으로 되돌린 뒤 카메라 설정이 백업과 바이트 단위로 같았습니다.

## 실기 확인 기록 (DC-S1M2 fw 1.5)

- Swift 도구: 원본 그대로 쓰기 성공. 흑백 TEST01을 연결 = 칸 번호로 등록했고, 카메라 화면에 흑백으로 적용되는 것을 확인했습니다.
- Rust `probe` 예제(`cargo run -p lumix-ptp --example probe`): 읽기(6.0초), 원본 그대로 쓰기(11.0초, 다시 읽은 결과 차이 0바이트), `register_lut`로 TEST01을 40번 칸에 덮어쓰기(백업, 쓰기, 다시 읽기 확인 통과).
- `crates/lumix-lut` 테스트는 실제 카메라에 썼던 TEST01 파일과 바이트 단위로 같은 결과를 만드는지 확인합니다. 테스트에 쓰는 설정 파일 원본에는 개인 설정과 시리얼이 들어 있어서 `tests/fixtures/local/`(git 제외)에 둡니다.

## 아직 확인하지 않은 것

- 33 이외 격자, `#LUMIXPHOTOSTYLE STD` 외 태그(지금은 거부합니다).
- 순서 변경, Windows(WPD) 전송.
- 다른 기종과 펌웨어: `0x9421`/`0x9422` 지원 여부, 이름 표 칸 크기(776)와 레코드 형식, "연결 = 칸 번호" 규칙, 스타일 코드, 0번·1번 기본 칸. 구조가 다르면 읽기에서 막히지만, 연결 규칙이나 스타일 코드가 다르면 구조 검사로 잡을 수 없습니다(실험적 쓰기의 남은 위험).
- 레코드 영역 끝 8바이트, 그리고 등록·선택 후 카메라가 바꾸는 상태 값(`0x2F3`, `0x1D2` 항목 등)의 의미.
